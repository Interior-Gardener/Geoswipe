===============================================================================
1. WHAT GEOSWIPE IS
===============================================================================
GeoSwipe is a web application (no installation, no login) for learning world
geography and Indian cultural heritage. A learner spins a realistic 3D Earth,
plays country / flag quizzes on it, opens an interactive map of 126 Indian
heritage sites, reads narrated "storybooks" about monuments, takes heritage
quizzes alone or against a friend in real time, asks an AI assistant
questions, generates an AI trip plan (with a PDF), and finds the safest route
to a site. Everything can also be controlled hands-free with webcam hand
gestures, and the gesture recognition runs entirely inside the browser, so the
video never leaves the user's computer.

===============================================================================
2. THE PROBLEM IT SOLVES
===============================================================================
- Heritage and geography are usually taught with static text, photos and flat
  maps -> little active exploration.
- A learner today must combine many separate tools (textbook, map app, weather
  site, quiz app, travel site) that share no context.
- Most tools assume mouse/keyboard/touch; none offer natural gesture control.
- Practical problem for a student team: free API tiers are tiny (NewsAPI 100
  calls/day, OpenWeather 1,000/day). Calling them on every page view breaks the
  app after a few visitors.
- Our first version recognised gestures in a Python server process, which
  required streaming webcam frames to the server (~900 KB/s per user =
  ~3.2 GB/hour), a privacy risk and too heavy for free hosting (512 MB RAM).

GeoSwipe's answer: one integrated browser app + in-browser gestures + a
quota-aware back end (shared cache, de-duplication, key pools).

5. SYSTEM ARCHITECTURE
===============================================================================
  +---------------------------------------------------------------------+
  | PRESENTATION TIER - React SPA on Cloudflare Pages                   |
  |  Globe | Heritage map | Games | Storybook | Trip/Safety | Chatbot   |
  |  Gesture subsystem: MediaPipe -> classifier -> stabiliser -> bus    |
  +-----------------------------+---------------------------------------+
                                | HTTPS REST (/api/*)  +  WSS (Socket.IO)
  +-----------------------------v---------------------------------------+
  | APPLICATION TIER - Node/Express 5 + Socket.IO on Render             |
  |  security headers, CORS allow-list, rate limiters                   |
  |  REST: heritage, quiz, flags, news, safety                          |
  |  Proxies: /api/ai, /api/weather, /api/maps  (keys live here only)   |
  |  Two-tier cache + in-flight de-dup + key pools                      |
  |  Multiplayer rooms (in memory, <= 500)                              |
  +--------------+---------------------------------+--------------------+
                 | Mongoose (TLS)                  | HTTPS
  +--------------v-------------+   +---------------v--------------------+
  | DATA TIER - MongoDB Atlas  |   | Groq, MapTiler, OpenWeather,       |
  | sites, quiz, countries,    |   | NewsAPI, Unsplash, Wikipedia,      |
  | api_cache, images, flags   |   | Overpass, flagcdn                  |
  +----------------------------+   +------------------------------------+

Why this shape:
  - Keys never reach the browser (anything named VITE_* is public in Vite).
  - One place (the server) controls quotas, caching and rate limits.
  - The browser does the heavy visual work (WebGL, maps, gestures) for free.

6. HOW A REQUEST FLOWS (example: user clicks the Taj Mahal on the map)
===============================================================================
 1. MapLibre fires a click on the "heritage-sites-icons" layer.
 2. Client calls GET /api/heritage-sites/Taj%20Mahal/details.
 3. Server escapes the name (no regex injection) and does an anchored,
    case-insensitive MongoDB findOne -> returns the HeritageSite document.
 4. Sidebar renders info. Client calls GET /api/weather/current?lat&lon.
 5. Server: getOrFetch('weather', "27.18,78.04", 4 h, fetchFn)
      a. memory Map hit and fresh?  -> return in ~5 ms
      b. else MongoDB api_cache hit and fresh? -> copy to memory, return
      c. else is the same key already being fetched? -> wait for that promise
      d. else call OpenWeather with the next key from the key pool;
         on HTTP 429 mark that key spent for today and try the next key
      e. store result in memory + MongoDB; return
      f. if upstream failed but an expired copy exists -> serve stale copy
 6. Same pattern for news (4 tiers), images, map style, safe places.
 7. The selected monument is kept in a React context (HeritageSelection), so
    storybook, quiz, chatbot, trip planner and safety pages open on it.

7. MODULE DEEP-DIVES
===============================================================================
7.1 3D GLOBE (client/src/EarthThreeJS.jsx, ~1,885 lines)
  - Earth sphere radius 10 (64x64 segments), textures: Albedo, Bump, Ocean,
    night lights; clouds sphere radius 10.08; atmosphere shell radius 12.8.
  - Renderer: ACES filmic tone mapping, exposure 1.2.
  - Atmosphere GLSL shader: alpha = (n.e)^4.5 * 12.0, opacity 0.8,
    colour = (0.35 + (n.e)/4.5, same, 1.0)  -> blue glow at the limb.
  - Country picking: countries GeoJSON -> earcut triangulation -> invisible
    meshes at radius 10.3. A THREE.Raycaster casts the click; the hit closest
    to radius 10.3 wins; lat = asin(y/10.3), lon = atan2(x, z) (degrees) to
    validate the hit is on the visible side. Border then flashes colours.
  - OrbitControls distance limits 15..100.
  - Adaptive FPS loop: measure FPS every second; if < 50 -> target =
    max(30, 0.9*fps); if > 90 -> target 120. Heavy work on a subset of frames.
  - Gestures: rotate_right/left -> rotate camera about Y by +-0.01875 rad;
    thumbs_up/down -> about X by +-0.0125 rad; zoom -> distance x0.9875;
    pinch -> distance x1.0125.

7.2 HERITAGE MAP & SIDEBAR (client/src/HeritagePage.jsx, ~3,694 lines)
  - MapLibre map; sites from /api/heritage-sites/geojson; circle + symbol
    layers with category icons (UNESCO, fort, cave, temple, monument, palace,
    museum, historic building). 6 styles via /api/maps/style/:name proxy.
  - Fly-to panel: search by name (autocomplete) or coordinates.
  - Sidebar: details, images, 360° iframe, Sketchfab model, weather/forecast,
    news (with location news), quick buttons for quiz/trip/safety.

7.3 GAMES
  - Country quiz (CountryQuiz.jsx / QuizPage.jsx): questions from
    /api/country-question (trivia API through server).
  - Flag game (FlagGuessGame.jsx): /api/random-flag-country gives a country +
    flagcdn image; learner must click that country on the globe; 10 rounds.
  - Heritage quiz (HeritageQuiz.jsx): /api/quiz/monument/:name or
    /api/quiz/all-india; 10 questions; 50:50 hint once per question; skip.
  - Question bank: 780 questions = 13 monuments x (20 easy + 20 medium +
    20 hard). Monuments: Taj Mahal, Red Fort, Qutub Minar, Golden Temple,
    Ajanta Caves, Ellora Caves, Hampi, Khajuraho Temples, Konark Sun Temple,
    Agra Fort, Humayun's Tomb, Mysore Palace, Gateway of India.

7.4 MULTIPLAYER (server/index.js + client Multiplayer*.jsx,
    client/src/utils/multiplayerSocket.js)
  - Room code: 6 characters from "ABCDEFGHJKLMNPQRSTUVWXYZ23456789" (no I, O,
    0, 1) -> 32^6 ~ 1.07 billion codes. Server re-validates
    /^[A-Za-z0-9_-]{4,64}$/ and sanitises names (<= 32 chars).
  - Modes: flag, quiz, heritage-quiz, heritage-monument. Max 2 players.
  - Server is the single source of truth: it generates questions, checks
    answers, keeps scores. Client only sends answers.
  - Flow: join-room -> (2nd player) game-started + new-question ->
    submit-answer (once per player) -> player-answered -> both answered ->
    show-result -> wait 3 s -> next round ... after round 10 -> game-over
    (winner or tie) -> scores reset (rematch possible).
  - Limits: <= 500 active rooms; 30 room actions per 10 s per socket;
    Socket.IO message size 64 KB; rooms empty or idle > 10 min are deleted
    (checked every minute).

7.5 STORYBOOKS (HeritageStoryBook.jsx + client/public/chapters/*.json)
  - 6 books: Ajanta Caves, Gateway of India, Raigad Fort, Shaniwar Wada,
    Taj Mahal, Trimbakeshwar Temple; 5 chapters each = 30 chapters, each with
    a JPG illustration and an MP3 narration.
  - JSON per chapter: title, text, image {url, alt, caption, focalPoint, fit}.
  - react-pageflip book; typewriter text; page-turn sound; Prev/Next, arrow
    keys and gesture clicks.
  - audio-to-captions.py (Whisper base, word timestamps) creates captions.

7.6 AI SERVICES (server/routes/aiProxy.js)
  - Single route POST /api/ai/chat with a "profile"; client cannot choose the
    model or parameters.
      heritage    : temperature 0.7, top_p 0.9, max_tokens 2000; system prompt
                    is grounded with up to 50 site names/categories from DB.
      safety      : temperature 0.4, max_tokens 1500.
      tripPlanner : temperature 0.6, max_tokens 4000, JSON mode.
  - Model from server env GROQ_MODEL (openai/gpt-oss-120b). /api/ai/status
    checks the model exists on the account. Empty completion (reasoning model
    used up the token budget) is detected and reported with a hint.
  - Key-shaped strings are redacted from logs. Limit: 20 AI requests / 5 min
    per IP.

7.7 TRIP PLANNER (TripPlannerPage.jsx, utils/tripPlannerAIService.js,
    utils/tripPlanPdf.js)
  - Builds a prompt with site context (name, category, city, state, summary,
    tips, timings, entry fee, best time, how to reach), user inputs and a
    weather summary (current + 5-day forecast).
  - Asks for JSON: title, summary, weatherAdvice, days[{day, focus,
    dateLabel, schedule[{time, activity, details}], foodRecommendations,
    travelSuggestions, notes}], costBreakdown{currency INR, stay, food,
    transport, entryFees, total, notes}, bookingLinks[{label, url}].
  - Response is cleaned (strips ```json fences), normalised, rendered, and
    exportable to PDF with jsPDF.

7.8 SAFETY NAVIGATION (SafetyNavigationPage.jsx, utils/safetyScoring.js)
  - Safe places: Overpass query for hospital/police/fire station within 3 km
    (server, cached 7 days). Fallback synthetic places if Overpass fails.
  - Score per route (see section 8). Badges Fastest / Shortest / Safest.
  - Emergency + evacuation modes, live navigation, contacts, AI guidance.

7.9 GESTURE CONTROL (components/CameraCapture.jsx,
    utils/gestureClassifier.js, utils/gestureBus.js, GlobalGestureCursor.jsx,
    GestureButton.jsx)
  - getUserMedia (front camera, <= 30 FPS).
  - MediaPipe HandLandmarker: VIDEO mode, GPU delegate, numHands 1,
    minHandDetectionConfidence 0.7, minHandPresenceConfidence 0.5.
    Model + WASM are self-hosted under /mediapipe and lazy-loaded (~10 MB
    first time, cached 30 days).
  - 21 landmarks -> mirror x -> classify -> stabilise -> publish on bus.
  - GlobalGestureCursor draws a cursor from the middle fingertip; mapping uses
    a 10 % calibration margin so screen edges are reachable.
  - GestureButton: if cursor is inside the button and a "click" gesture
    arrives -> run onClick (with a small press animation).
  - Gesture bus is "scoped": each component gets its own handle; off(event)
    only removes that component's handlers (fixes a real bug where the globe
    unsubscribed the global cursor).

  Supported gestures:
    Open palm      -> move cursor          OK sign        -> click
    Two fingers R/L-> rotate globe L/R     Thumbs up/down -> rotate up/down
    L sign         -> zoom in              Pinch          -> zoom out
    Index point    -> recognised (pointing)

8. THE ALGORITHMS AND THE MATHS
===============================================================================
8.1 Gesture classification (landmark indices: 0 wrist, 2 thumb MCP,
    4 thumb tip, 6/8 index PIP/tip, 10/12 middle, 14/16 ring, 18/20 pinky)
  d(a,b) = sqrt((xa-xb)^2 + (ya-yb)^2)          (2-D distance)
  mirror:  x' = 1 - x
  finger open  <=>  y_tip < y_pip                (image y grows downward)
  thumb extended <=> d(4,2) > 0.07 AND d(4,0) > 0.12
  delta = d(4,8) (thumb-index), tau = d(4,0) (thumb-wrist)
  Rules, first match wins:
    click        delta < 0.05 AND middle, ring, pinky open
    thumbs_up    thumbExt AND all fingers closed AND y4 < y0 - 0.08
    thumbs_down  thumbExt AND all fingers closed AND y4 > y0 + 0.08
    pinch        delta < 0.04 AND middle, ring, pinky closed
    zoom         thumbExt AND only index open AND delta > 0.13
    index_point  only index open AND NOT thumbExt AND tau < 0.10
    cursor_move  all four fingers open AND tau >= 0.08
    rotate L/R   index+middle open, ring+pinky closed; x8 < x0 -> left
    unknown      otherwise

8.2 Stabiliser (Algorithm)
  for each frame at time t:
    if t - lastProcessed < 50 ms: skip                  (20 FPS cap)
    if no hand: reset count, clear cursor; return
    g = classify(mirror(landmarks))
    count = (g == previous) ? count + 1 : 1
    if count >= 5 and g != unknown:
        if g == click: emit only if t - lastClick >= 1.0 s
        else emit g
    if g == cursor_move: emit cursor (landmark 12)
  Minimum latency: L = (N-1) * ceil(Delta/T) * T
    30 FPS camera: L = 4 * 2 * 33.3 = 267 ms, effective rate 15 FPS.

8.3 Cursor mapping
  X = clamp((x' - 0.1) / 0.8 * W, 0, W),  Y = clamp((y - 0.1) / 0.8 * H, 0, H)

8.4 Globe picking
  lat = asin(y / 10.3) * 180/pi ;  lon = atan2(x, z) * 180/pi

8.5 Cache quota bound
  calls/day <= S * ceil(24 / theta)    (S = places, theta = TTL hours)
  weather: 126 * 6 = 756/day < 1,000 free limit.

8.6 Key pool (round-robin)
  i = (cursor + hop) mod n ; skip keys exhausted today or used >= soft cap
  (NewsAPI 90, OpenWeather 900, MapTiler 3000 per key per day);
  on 429/401/403 mark key exhausted for the UTC day; on success
  cursor = (i+1) mod n. Counters reset when the UTC date changes.

8.7 Safety score
  Haversine: a = sin^2(dphi/2) + cos phi1 cos phi2 sin^2(dlambda/2)
             d = 2 r atan2(sqrt(a), sqrt(1-a)),  r = 6,371,000 m
  Coverage C = clamp(1 - mean(nearest safe-place distance over <=12 route
               points) / 5000, 0, 1)
  Weather risk W = 0.15 (+0.45 storm | +0.30 rain/snow | +0.20 fog/mist/haze)
                   +0.20 visibility < 3 km, +0.15 wind > 10 m/s,
                   +0.15 temp > 41 C or < 3 C  (clamped 0..1)
  Alert risk A = max severity (low .2, medium .45, high .75, critical 1)
  S = 55*C + 25*(1-W) + 20*(1-A)            (0..100)
  Composite = 0.7*S + 20*(minDuration/duration) + 10*(minDistance/distance)

8.8 COCOMO (report Chapter 3)
  KLOC = 26.0 -> organic: E = 2.4*26^1.05 = 73.5 person-months,
  D = 2.5*E^0.38 = 12.8 months, P = 5.7 people (upper bound; libraries
  reduce real effort).

9. BACK END: CACHING, KEY POOLS, NEWS TIERS, RATE LIMITS
===============================================================================
  server/services/cache.js   getOrFetch / peek / put / stats
     - memory Map + MongoDB "api_cache" collection
     - undefined from fetchFn = failure (not cached); null and [] ARE cached
     - stale-on-failure; in-flight de-duplication
     - Mongo TTL index 7 days on cachedAt (keeps DB under 512 MB)
  server/services/keyPool.js  createKeyPool(name, keys, {dailyLimitPerKey})
  TTLs: weather 4 h (coords rounded to 2 decimals ~1.1 km), news 12 h per
        tier, safety alerts 3 h, safe places 7 days, MapTiler style 24 h,
        images permanent (own collections).
  News tiers: L1 monument -> L2 city -> L3 state -> L4 India heritage; each
        tier cached separately, shared by all monuments in that place.
  Rate limits (per IP): whole API 1,200 / 15 min; AI 20 / 5 min; weather
        60 / 5 min; maps 3,000 / 5 min. Sockets: 30 room actions / 10 s.
  Diagnostics: GET /api/diagnostics probes MongoDB, Groq, OpenWeather,
        NewsAPI, MapTiler, Unsplash, trivia API, flagcdn, Overpass, Wikipedia.

12. SECURITY MEASURES
===============================================================================
  - Only VITE_API_URL is public; all keys in server/.env (Render dashboard).
  - Headers: nosniff, X-Frame-Options DENY, Referrer-Policy no-referrer,
    Permissions-Policy, CSP "default-src 'none'; frame-ancestors 'none';
    sandbox", CORP same-site, HSTS in production, X-Powered-By removed.
  - CORS allow-list for HTTP + WebSocket; wildcard *.geoswipe.pages.dev
    matched on a parsed URL (15 attack cases tested and rejected).
  - escapeRegex / exactMatchRegex for Mongo queries; sanitizeText trims,
    length-caps, removes control characters.
  - Generic error messages to clients; details only in server logs (with key
    redaction).
  - Webcam frames never leave the browser; front end Permissions-Policy
    camera=(self), geolocation=(self).

  Prerequisites: Node.js >= 18, MongoDB (local or Atlas), Git.
  1. npm install ; cd client && npm install ; cd ../server && npm install
  2. copy server/.env.example -> server/.env and fill:
       MONGODB_URI, GROQ_API_KEY, GROQ_MODEL, MAPTILER_API_KEYS,

                           server http://localhost:3000
     Health: http://localhost:3000/api/diagnostics
  Other: cd client && npm run build | npm run lint ; cd server && npm run dev

DEPLOY (free)
  1. MongoDB Atlas M0 cluster; run seed scripts against it.
  2. Render: New -> Blueprint (render.yaml) or Web Service, rootDir server,
     npm ci, node index.js, HOST=0.0.0.0, NODE_ENV=production, health path
     /health; add secrets in dashboard.
  3. Cloudflare Pages: root client, build "npm run build", output dist,
     env VITE_API_URL=https://<render-url>.
  4. Set ALLOWED_ORIGINS=https://geoswipe.pages.dev,https://*.geoswipe.pages.dev
  5. Check /api/diagnostics and test every page (camera needs HTTPS).

17. VIVA / INTERVIEW QUESTIONS WITH ANSWERS
===============================================================================
Q: What is GeoSwipe in one line?
A: A no-install web platform that teaches geography and Indian heritage
   through a 3D globe, heritage map, storybooks, quizzes, multiplayer, AI and
   touch-free hand gestures.

Q: Why run gesture recognition in the browser and not on the server?
A: Privacy (video never leaves the device), cost (old design ~3.2 GB per
   user-hour of upload and a Python process that did not fit 512 MB), and
   latency (no network round trip). Accuracy is unchanged: 0 mismatches on
   20,000 test poses between the old Python and new JS classifier.

Q: Why a rule-based classifier instead of training a neural network?
A: MediaPipe already gives accurate landmarks; the 9 gestures are
   geometrically distinct, rules are explainable, need no training data,
   cost 0.145 microseconds per pose and behave identically to the earlier
   Python version. A learned classifier is future work.

Q: How do you stop accidental clicks?
A: Stabiliser: same pose for 5 consecutive processed frames + 1 s cooldown
   between clicks + 20 FPS cap. In simulation it emitted 0 wrong gestures
   even when 53.8 % of frames were misclassified.

Q: What is the latency of a gesture?
A: L = (N-1)*ceil(Delta/T)*T = 267 ms at 30 FPS (measured the same).

Q: How does the app survive tiny free API quotas?
A: Results are cached per place (126 sites) in memory + MongoDB and shared by
   all users, concurrent requests are merged, stale data is served if the
   provider fails, and keys are pooled with soft caps. Upstream calls depend
   on sites x refreshes, not on users. Weather max = 756 calls/day.

Q: Why MongoDB?
A: Heritage data is nested documents (info, routes, media, visitor info) and
   MongoDB has a 2dsphere geospatial index and TTL indexes for the cache.

Q: How are API keys protected?
A: They exist only on the server. The browser calls /api/ai, /api/weather,
   /api/maps proxies. Vite inlines any VITE_* variable into public JS, so we
   allow only VITE_API_URL.

Q: How does multiplayer prevent cheating?
A: The server generates questions, checks answers, accepts one answer per
   player per round and keeps scores; the client only submits an answer.

Q: How is the right country picked when clicking the globe?
A: Countries are earcut-triangulated into invisible meshes at radius 10.3;
   a raycaster finds the hit nearest that radius; lat/lon from asin/atan2
   validates it.

Q: What does the AI do and how is it controlled?
A: Three server profiles (heritage chat, safety advice, trip-plan JSON). The
   model and temperature are fixed on the server; heritage answers are
   grounded with the site list; trip plans follow a JSON schema.

Q: How is the safety score computed?
A: S = 55*coverage + 25*(1-weatherRisk) + 20*(1-alertRisk); coverage from
   haversine distance of route points to hospitals/police/fire stations.

Q: What are the limitations?
A: Gesture benchmark is synthetic (needs a real-user study); latency depends
   on network and free-tier cold start (23 s); keyword news can be
   off-topic; no usability / learning-gain study yet (SUS planned).

Q: What is your main contribution?
A: Integration of all these learning features into one browser workflow,
   plus privacy-preserving gestures and a quota-aware back end that let a
   student team run it for Rs 0 per month.

18. LIMITATIONS AND FUTURE SCOPE
===============================================================================
Limitations: synthetic gesture evaluation only; fixed absolute thresholds;
free-tier cold start; news relevance; two-player rooms only; no learner
accounts; no measured learning gain or usability yet.
Future: SUS + pre/post-test user study; real-webcam validation and
hand-size-normalised thresholds or a learned classifier; PWA / mobile /
offline; storybooks and quizzes for all 126 sites; regional languages;
accounts, progress tracking, teacher dashboards; whole-class multiplayer
with shared room store (e.g., Redis); better news filtering; retrieval-
grounded AI with citations.
